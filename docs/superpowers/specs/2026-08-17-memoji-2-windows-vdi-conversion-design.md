# Memoji 2.0 기본 전환 및 Windows VDI 시험 배포 설계

Date: 2026-08-17
Approved direction: A안 — 구버전은 복구 가능하게 봉인하고 GitHub 기본 브랜치와 배포물은 Tauri 2.0으로 전환

## 목적

기존 Memoji 1.0 설치 앱과 오래된 기본 브랜치가 계속 노출되는 상태를 끝내고, 현재 `codex/memoji-2-ga-uiux` 작업본을 Memoji의 유일한 현행 제품 소스로 전환한다. 구버전 소스와 사용자 데이터는 삭제하지 않고 별도 보관하며, Windows VDI에서 사용자가 직접 실행하고 검증할 수 있는 Tauri 2.0 시험 배포물을 만든다.

## 현재 확인된 상태

- macOS에 설치되어 보이는 구버전은 `/Volumes/doublejun/application/Memoji.app`의 Memoji 1.0.0이다.
- 새 제품 코드는 `.worktrees/memoji-2-ga-uiux`에 있으며 패키지·Tauri 버전은 2.0.0이다.
- 새 개발 앱은 `com.memoji.app.dev`, 정식 앱은 `com.memoji.app` 식별자를 사용한다.
- LiteRT-LM 0.16.0 C API와 Gemma 4 E2B의 인프로세스 생성 경로는 macOS 개발 환경에서 확인됐다.
- Windows Authenticode 인증서와 GitHub Actions 서명 비밀값은 아직 없다.
- 따라서 이번 Windows 산출물은 정식 GA가 아니라 `v2.0.0-rc.1` unsigned VDI pilot으로 분류한다.

## 선택한 전환 방식

### Git 보관선

1. 전환 직전 원격 `main` 커밋을 `archive/memoji-v1-final` 브랜치와 `v1.0.0-legacy` 태그로 보관한다.
2. 현재 Tauri 2.0 작업본의 변경을 검토 가능한 커밋 단위로 정리한다.
3. 검사와 비밀정보 점검을 통과한 Tauri 2.0 브랜치를 원격에 먼저 푸시한다.
4. 원격 `main`은 이 브랜치로 fast-forward 전환한다. 강제 푸시는 사용하지 않는다.
5. 전환 뒤에도 구버전 이력은 보관 브랜치와 태그에서 복구할 수 있어야 한다.

### 로컬 설치 앱 보관선

1. 실행 중인 Memoji 1.0을 정상 종료한다.
2. 설치 앱은 날짜가 붙은 보관 폴더로 이동하고 즉시 삭제하지 않는다.
3. 기존 데이터베이스는 앱과 분리해 별도 백업한 뒤 복사본으로 마이그레이션을 검증한다.
4. 새 앱의 기본 설치·실행이 확인된 뒤에만 구버전 앱을 활성 위치에서 제거한다.

### 기본 브랜치 정리선

`main`에는 다음만 남긴다.

- React/TypeScript 기반 Memoji 2.0 프런트엔드
- Tauri 2/Rust 백엔드와 SQLite 마이그레이션
- Milkdown 편집기, 작업·일정·검색·지식·AI 제안 기능
- LiteRT-LM/Gemma 로컬 AI 통합 및 번들 준비 스크립트
- 테스트, 릴리즈 게이트, SBOM·체크섬 생성, 운영 문서

다음은 기본 브랜치 및 배포물에서 제외한다.

- Memoji 1.0 전용 UI·설정·패키지
- 임시 캡처, 영상 제작물, 로컬 로그와 빌드 디렉터리
- 개인 장비 경로를 가리키는 산출물
- 모델 바이너리와 서명 인증서 같은 배포 비밀·대용량 비추적 파일
- 동일 목적의 중복 스크립트 중 검증되지 않은 이전 경로

## 데이터 보존과 전환

- 사용자 DB는 삭제 대상이 아니다.
- 마이그레이션 전 원본 DB의 체크섬과 백업 경로를 기록한다.
- 1.0/2.x 이전 스키마를 모두 감지하고 순차 마이그레이션한다.
- 마이그레이션은 원본을 덮어쓰기 전에 복사본으로 성공 여부를 확인한다.
- 페이지 수, 리비전 수, 휴지통·태그·작업 레코드 수를 전후 비교한다.
- 실패하면 새 앱 실행을 중단하고 원본 DB를 그대로 복구할 수 있어야 한다.

## Windows VDI 시험 배포물

### 산출물 구성

배포 산출물은 `Memoji-2.0.0-rc.1-windows-x64-vdi-unsigned.zip`으로 만들며 최소한 다음을 포함한다.

- Tauri 기반 `Memoji.exe`
- `memoji-vdi-benchmark.exe`
- Windows용 LiteRT-LM 런타임 DLL과 필요한 종속 DLL
- 승인된 Gemma 4 E2B 모델 파일 또는 검증 가능한 내부 모델 배치 절차
- 런타임·모델 호환성 명세
- `SHA256SUMS.txt`
- CycloneDX SBOM
- 설치·첫 실행·VDI 벤치마크·로그 수집·제거 절차가 적힌 한국어 README

### 빌드 방식

- Windows x64 GitHub Actions 러너 또는 실제 Windows 빌드 호스트에서 MSVC 대상으로 빌드한다.
- VDI 시험판은 `-AllowUnsigned` 경로를 명시적으로 사용하며 파일명과 문서에 unsigned 상태를 표시한다.
- Windows용 런타임/모델이 없는 경우 앱만 성공했다고 배포 완료로 간주하지 않는다.
- 앱, 벤치마크, 런타임, 모델의 체크섬이 모두 생성된 경우에만 릴리즈 자산으로 올린다.
- 일반 설치 실행물과 완전 오프라인 VDI 번들은 서로 다른 자산으로 구분한다.

### VDI 검증 항목

사용자가 VDI에서 다음을 직접 확인할 수 있어야 한다.

1. 인터넷이 차단된 상태에서 앱 실행
2. 기존 DB 복사본 가져오기와 전체 페이지 열람
3. 노트 작성·저장·재실행 후 복원
4. Gemma 4 E2B 로드 및 짧게 256, 기본 1024, 길게 2048 이상의 생성
5. AI가 localhost 포트나 외부 서버 없이 인프로세스로 동작하는지 확인
6. CPU/RAM 사용량, 첫 토큰 지연, 생성 속도 기록
7. EDR 차단·DLL 누락·모델 로드 실패 여부와 로그 수집
8. 제거 후 사용자 DB가 유지되는지 확인

## 버전과 릴리즈 정책

- 원격 기본 브랜치: Tauri 2.0 전환 완료 코드
- 시험 태그: `v2.0.0-rc.1`
- GitHub 릴리즈: prerelease, `Unsigned VDI Pilot` 표기
- 정식 태그 `v2.0.0`: Authenticode 서명, 대상 VDI 실행, EDR 허용, 성능 기준을 모두 통과한 뒤에만 생성
- macOS 개발 검증이나 GitHub Actions 성공만으로 Windows VDI GA라고 주장하지 않는다.

## 안전장치와 롤백

- 사용자 기존 변경을 통째로 덮어쓰지 않는다.
- 원격 `main` 전환 전 보관 브랜치·태그가 실제 원격에 존재하는지 재확인한다.
- 강제 푸시, `git reset --hard`, 광범위 재귀 삭제를 사용하지 않는다.
- 추적 대상 파일을 삭제하기 전 새 버전에서 미참조임을 검색하고 테스트한다.
- 새 `main`에 문제가 있으면 `archive/memoji-v1-final`로 복구 브랜치를 즉시 만들 수 있어야 한다.
- 로컬 구버전 앱과 DB 백업은 새 앱 및 VDI 시험 결과가 확인될 때까지 유지한다.

## 완료 기준

- GitHub에 `archive/memoji-v1-final`과 `v1.0.0-legacy`가 존재한다.
- 원격 `main`의 버전, Tauri 설정, 대표 UI가 모두 Memoji 2.0을 가리킨다.
- 구버전 전용 코드·배포물·임시 파일이 기본 브랜치 산출물에 포함되지 않는다.
- TypeScript 검사, 단위 테스트, 프로덕션 빌드, Rust 포맷·Clippy·테스트가 통과한다.
- 커밋 대상 비밀정보 및 대용량 파일 검사가 통과한다.
- Windows x64 VDI zip과 체크섬·SBOM·한국어 안내서가 생성된다.
- GitHub `v2.0.0-rc.1` prerelease에서 시험 파일을 내려받을 수 있다.
- 실제 VDI 검증 전에는 정식 GA 완료로 표시하지 않는다.

## 비목표

- 이번 단계에서 코드서명 인증서를 새로 발급받는 일
- 실제 사용자 VDI의 EDR 정책을 우회하거나 변경하는 일
- 사용자 확인 없이 기존 DB나 구버전 백업을 영구 삭제하는 일
- Windows VDI 검증 전에 `v2.0.0` 정식 GA를 선언하는 일
