# Memoji 2.0 상호작용 보수 및 전수 QA

작성일: 2026-08-16

## 목적

실제 Tauri 개발 창과 브라우저 격리 컨텍스트에서 재현한 상호작용 결함을 수정하고, 버튼의 존재가 아니라 사용 결과가 저장·표시되는지를 기준으로 검증한다.

## Refero reference lock

- 기본 시각 언어: shadcn UI의 흰 캔버스, 얇은 중립색 경계, 8px 간격 리듬, 작은 기능 아이콘.
- 편집기 상호작용: Resend의 링크 흐름처럼 `선택 → 입력 → Enter → 적용 결과`가 즉시 확인되어야 한다.
- 작업 공간 밀도: Replo/Skiff 계열의 조밀한 생산성 UI를 따르되 현재 3열 셸과 정보 구조는 유지한다.
- 금지 범위: 장식적 재설계, 새로운 색 체계, 도구 모음의 무근거 재배치. 이번 작업은 발견 가능성, 동작 피드백, 저장 일관성 보수에 한정한다.

| 항목 | 실제 재현/코드 근거 | 수정 계약 | 완료 증거 |
| --- | --- | --- | --- |
| 창 드래그 | 상단 헤더의 빈 틈만 `data-tauri-drag-region` 대상이고 자식 레이어가 드래그 표면을 막음 | 상단 바의 비대화식 영역 전체를 명시적 드래그 표면으로 만들고 버튼은 클릭 가능하게 유지 | 컴포넌트 테스트 + 네이티브 창 이동 |

| `+ 속성` | 비활성 안내만 있는 자리표시자 | 속성 패널을 열고 상태·마감일·태그를 편집하여 문서 메타데이터에 저장 | 컴포넌트/메타데이터 테스트 + 수동 QA |
| 편집기 도구 | 링크는 선택 시 동작하지만 피드백이 약하고, 일반 문단 들여쓰기/내어쓰기는 무반응 | 링크 흐름을 명확히 유지하고 목록/일반 문단 모두 들여쓰기 결과가 발생하도록 보강; 전체 버튼 교차 점검 | 명령 테스트 + 브라우저 수동 QA |

## 완료 판정 원칙

- 버튼 클릭만으로 통과 처리하지 않는다. DOM/Markdown/SQLite 중 해당 기능의 영속 결과를 확인한다.
- 브라우저 테스트와 Tauri 네이티브 테스트를 분리해 기록한다.
- Windows VDI 배포 완료 판정은 이 문서 범위가 아니다. 실제 Windows 대상, 모델 번들, 서명 검증 없이는 GA 완료로 표기하지 않는다.

## 구현 및 검증 기록

### 구현 결과

1. `TopCommandBar`에 상단 바 전체를 덮는 비대화식 드래그 표면을 추가했다. 버튼과 상태 컨트롤은 드래그 표면보다 위에 있어 기존 클릭 동작을 유지한다.
2. 캘린더 보기 이름을 `월간/주간/일간`으로 바꾸고 제목과 이전·다음 버튼의 접근성 이름도 각각 달/주/날짜 단위에 맞췄다.
3. 좌측 패널 내부의 중복 축소 버튼을 제거했다. 좌우 패널 열기·닫기는 상단 명령 바가 단일 소유자다.
4. AI 출력 프리셋을 짧게 256, 기본 1024, 길게 2048 토큰으로 조정했다. Gemma 4 E2B 네이티브 설정과 요청 정규화 상한은 4096 토큰으로 통일했다.
5. DB 가져오기가 원본에 존재하는 모든 `page_revisions` 행과 원본 스키마 버전을 읽는다. 같은 페이지/리비전 본문은 건너뛰고, 번호가 같지만 본문이 다르면 새 번호를 배정하여 기존 이력을 덮어쓰지 않는다. 가져온 모든 이력은 속성 패널에서 열람하고 새 리비전으로 복원할 수 있다.
6. `+ 속성`은 우측 속성 탭을 열며, 상태·마감일·태그를 Markdown 메타데이터로 저장한다. 필드에는 고유 `id`와 `name`도 제공한다.
7. 목록에서는 기존 `sink/lift`를 사용하고, 일반 문단에서는 두 칸의 영속 공백을 추가·제거하도록 들여쓰기/내어쓰기를 보강했다. `naver.com` 같은 도메인은 `https://naver.com`으로 정규화하고 실행 가능한 위험 스킴은 거부한다.
8. 버전 복원은 일반 페이지 저장 경로 한 번만 사용한다. 네이티브 복원 후 다시 저장하여 리비전이 두 번 늘어날 수 있던 리뷰 발견 사항을 회귀 테스트로 고정했다.

### 편집기 도구 전수 교차 점검

격리된 Chrome DevTools 컨텍스트에서 빈 테스트 문서를 만들고 클릭 이후 DOM 또는 직렬화된 Markdown을 확인했다.

| 도구 | 확인 결과 |
| --- | --- |
| 문단 형식 | 본문과 제목 1~6 전환 결과 확인 |
| 굵게/기울임/취소선 | 각각 `strong`/`em`/`del` 결과 확인 |
| 인라인 코드 | `code` 결과 및 충돌 서식 제거 확인 |
| 글머리/번호 목록 | `ul`/`ol` 결과 확인 |
| 체크리스트 | task-list 결과 확인 |
| 링크 | `naver.com` 입력 후 `https://naver.com` href 확인 |
| 이미지 | URL 삽입 UI와 `img` 결과 확인 |
| 표 | 3x3 표 생성 확인 |
| 코드 블록/수식 블록 | 각각 코드 블록과 LaTeX 블록 결과 확인 |
| 인용/구분선 | `blockquote`/`hr` 결과 확인 |
| 글자색/이모지 | 색상 span 직렬화와 이모지 삽입 확인 |
| 문단 내어쓰기/들여쓰기 | 일반 문단의 두 칸 추가와 제거, 목록의 sink/lift 확인 |

여러 일반 문단을 한 번에 목록으로 전환하면 Milkdown이 연속 문단을 한 목록 항목의 continuation으로 직렬화할 수 있다. 이는 유효한 Markdown이지만, 각 문단을 무조건 별도 목록 항목으로 분할하는 별도 편집 정책은 이번 결함 보수 범위에 포함하지 않았다.

### 자동 검증

- `npm run check`: TypeScript 검사, 29개 파일 112개 테스트, Vite production build 통과.
- `cargo test --manifest-path src-tauri/Cargo.toml`: Rust 105개 통과, 실 다운로드 모델이 필요한 3개만 명시적으로 ignored, 실패 0.
- `cargo test --manifest-path src-tauri/Cargo.toml database::tests`: DB 가져오기 10개 통과.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`: 경고 0.
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`: 포맷 차이 0.
- 회귀 테스트는 드래그 영역, 중복 사이드바, 캘린더 단위, AI 프리셋/상한, DB 이력, 속성 편집/복원, 링크 정규화, 일반 문단 들여쓰기/내어쓰기를 포함한다.
- Milkdown이 지연 로드하는 Vue esm-bundler feature flag도 Vite에 고정하여 개발 콘솔 경고를 제거하고 editor-vue production chunk를 약 62.47 kB에서 55.64 kB로 줄였다.

### 수동 브라우저 및 Tauri 확인

- 브라우저: `http://localhost:1420/`의 격리 컨텍스트에서 속성 저장, 달력 월간/일간 제목과 이전·다음 날 이동, 전체 편집기 도구를 확인했다.
- 콘솔: 격리 QA 데이터를 초기화한 새로고침 기준으로 Vite 연결과 React 개발 안내 외 오류·경고·접근성 issue가 없다.
- 네이티브: 현재 worktree의 `src-tauri/target/debug/app`을 정확한 UNIX PID로 식별했다. 상단 바 안쪽 28px 지점을 드래그한 뒤 창 위치가 `(360,117)`에서 `(440,177)`로 이동했다.
- 개발 서버: Vite가 `[::1]:1420`에서 LISTEN 중이며 `tauri dev --config src-tauri/tauri.dev.conf.json`과 개발 바이너리가 함께 실행 중이다.

### 데이터 및 배포 경계

- 원본 DB에 실제로 남아 있는 모든 페이지와 `page_revisions`는 가져오고 표시한다. 구버전이 과거 편집 내용을 별도 행으로 저장하지 않았다면 존재하지 않는 과거 본문을 사후 복원할 수는 없으며, 그 DB의 최종 페이지 본문만 가져올 수 있다.
- macOS 개발 환경에서 Windows VDI의 서명, 설치 권한, CPU 가속, 실제 메모리 압박과 모델 응답 성능까지 증명할 수 없다. Windows 배포 완료 판정은 서명된 산출물과 실제 대상 VDI에서 별도로 수행해야 한다.
